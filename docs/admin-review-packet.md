# Private administrator review packets

`/admin/revision-learning-paths` can open a local JSON packet after the existing server has verified the signed-in account as an administrator. Importing does not publish a lesson or grant access. The file, SVG image URLs and temporary answers stay in the mounted tab's memory; there is no upload, storage adapter or progress/reward action.

The packet is cleared on replacement, explicit clear, authentication changes, authorization failure, route unmount, page exit, or restoration from the browser back/forward cache. Reloading requires selecting the file again. Within the private catalogue, lesson selection is local and does not leave this review session. Authorization is rechecked before reading a file, after validating it, before selecting a lesson, on focus/visibility, and at most 30 seconds apart while idle. Content is hidden during revalidation while temporary answers remain mounted.

## Version 1 contract

Top-level keys, all required and with no extra keys:

- `format`: `flightpath.admin-review`
- `version`: `1`
- `title`: the review packet's plain-text title
- `createdAt`: ISO 8601 date-time with timezone
- `catalog`: 1–129 entries, each containing `id`, `code`, `title`, `subjectId`, `subject`, `order`, `status`, and `notes` (plain-text array)
- `documents`: object keyed by catalogue ID, containing native Handbook documents
- `assets`: object keyed by absolute logical `.svg` paths, each containing `mime: "image/svg+xml"` and `content` (SVG text)

The executable, strict schema and limits are in `src/lib/lp/admin-review-packet.ts`. A minimal synthetic example is generated by `tests/fixtures/admin-review-synthetic.cjs`. Never place real private candidate documents, assets, packets, or content ledgers in this public repository.

Catalogue IDs use `ciaac/<subjectId>/<container>/<lesson>` with lowercase ASCII slug components. Codes and IDs must be unique. `order` is a non-negative integer. The document's title must match its catalogue entry. Fewer than 129 entries are accepted with an explicit missing-count warning; the importer does not infer completeness from a file's presence or title.

### Status and source claims

- `published`: must match an ID returned by the freshly authorized server catalogue. No packet body is allowed. The selected body is fetched only from the existing authenticated endpoint.
- `candidate`: a private review body is required; no publication or source approval is implied.
- `source-pending`: a review body is required and source reservations remain visible.
- `incomplete`: a body may be present or absent. An absent body is shown as pending.

A packet cannot replace an existing published lesson under another status. Notes and source flags are displayed independently of the native lesson renderer. Native approved-aircraft presentation falls back to the Handbook content layout when a stage has no teaching board, preserving all source cards.

### Documents and images

The supported schema follows `HandbookLearningPathDocument`, with the native approved renderer's `exerciseFigures` and figure `heading`, `assetAspectRatio`, `crop`, and `focus` fields. Content stages may carry an optional plain-text `id`. Question, exercise, activity and board references must resolve. Unknown keys, prototype-related keys, duplicate JSON keys, malformed structures, executable markup, and invalid bounds are rejected.

Every figure path, including exercise and stage figures, must have an asset in the same packet. Extra assets and bodies are rejected. Figure paths cannot contain remote URLs, query strings, traversal or data/JavaScript URLs. Sources may link to public HTTPS pages as ordinary links; they are not fetched by import.

SVGs are parsed as XML, validated, reserialized and used exclusively through image Blob URLs. The allowlist permits inert vector/text/defs, gradients, clipping, masks, patterns and markers; their local `url(#id)` and accessibility references must resolve. It rejects scripts, events, HTML, `foreignObject`, image/use elements, animation, CSS style elements/attributes, processing instructions, DOCTYPE/entities and external references. Presentation attributes are supported. Do not strip or rewrite substantive lesson text to make validation succeed; correct the source or report the incompatible field. Any explicit non-visual normalization used when producing a private packet should be recorded with that packet.

Limits include 32 MiB UTF-8, JSON depth 32, 400,000 JSON nodes, 2,000 members per collection, 1,500 assets, 524,288 UTF-16 code units per SVG string, 4,000 elements per SVG and 300,000 SVG elements in total. Native schema arrays, strings, percentages, dimensions, option orders and indices have additional bounds. URLs allocated during a failed materialization are rolled back; disposal is idempotent.

## Local checks

Run these against the final tree:

- `node tests/admin-review-packet.cjs`
- `node tests/admin-review-workspace.cjs`
- `node tests/admin-review-native-import.cjs`
- Existing `tests/admin-learning-path-review*.cjs` regressions
- TypeScript, scoped ESLint, and the production build

Tests use only synthetic imported material and mocked authentication. They do not establish real Supabase session access, production deployment, content completeness, source approval or publication readiness.
